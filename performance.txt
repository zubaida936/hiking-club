CMS / site performance fix (2026-10-22)
=======================================

Result
------
Pages that took about 4 s now load in about 120 ms.

Why it was slow
---------------
Docker on Windows runs inside a Linux virtual machine (WSL2), but the project
lives on the Windows drive (C:\Dev\...). Every page load made PHP read hundreds
of library files from vendor/ across that boundary, which is very slow. Booting
Laravel took 5.3 s, and only 0.1 s of that was actual work. The Vite dev server
had the same problem with node_modules/.

The fix
-------
- vendor/ and node_modules/ are now stored in Docker volumes inside the Linux
  machine (compose.yaml). Your own code still comes from C:\Dev, so edits show
  up live as before.
- The PHP container installs the libraries automatically the first time it
  starts (docker/php/dev-entrypoint.sh). A lock stops app, queue and scheduler
  from all installing at once.
- PHP now caches file-path lookups (docker/php/conf.d/dev.ini).

Measurements
------------
                              Before     After
  Public home page            4.3 s      ~0.13 s
  CMS login page              1.9 s      ~0.12 s
  CMS stylesheet from Vite    38 s       ~0.05 s
  Full test suite             48 s       17 s

Formatting, static analysis and all 84 tests pass. Commit: 18c6821 on main.

How it was measured
-------------------
Run these from the project root in PowerShell, with the stack up
(docker compose up -d).

1. Page response times (each URL requested 3 times; the first request warms
   the caches, so look at the 2nd and 3rd numbers):

   foreach ($u in 'http://localhost:8080/up','http://localhost:8080/','http://localhost:8080/admin/login','http://localhost:5173/resources/css/admin.css') {
       $ms = 1..3 | % { (Measure-Command { try { Invoke-WebRequest $u -UseBasicParsing -TimeoutSec 90 | Out-Null } catch {} }).TotalMilliseconds }
       "{0,-48} {1}" -f $u, (($ms | % { '{0:N0} ms' -f $_ }) -join ' / ')
   }

   /up is Laravel's health check: it does almost nothing, so its time is
   close to the pure cost of booting the framework.

2. Laravel boot time vs. CPU time (shows whether PHP is working or waiting on
   files). Before the fix: real 5.26 s but user 0.11 s, i.e. almost all
   waiting on disk:

   docker compose exec -T app sh -c 'time php artisan --version'

3. Number of dependency files PHP and Vite have to read:

   docker compose exec -T app sh -c 'find vendor -type f | wc -l'
   docker compose exec -T node sh -c 'find node_modules -type f | wc -l'

4. CPU/memory per container (rules out a busy or out-of-memory container):

   docker stats --no-stream

5. Test suite duration (printed at the end as "Duration"):

   docker compose exec app php artisan test --compact

Things to know
--------------
- First stylesheet load: each time the node container starts, the first
  stylesheet load still takes about 30 s while Tailwind builds it. After that
  it is instant.
- Editor autocomplete: the vendor/ folder visible on Windows is now an old copy
  that the app no longer uses. If your editor's PHP autocomplete relies on it,
  it won't see new packages until they are copied out of the container.
- Further speed-up: the biggest remaining gain would be moving the project into
  the WSL Linux filesystem (for example \\wsl$\Ubuntu\home\...), so your own
  code doesn't cross that boundary either.

Slow first load after the node container starts (2026-10-24)
=============================================================

Why
---
The HTML is fast from the first request; the browser waits on the stylesheet.
Vite builds each file on its first request, and Tailwind has to scan the
project files on the Windows drive to find the classes in use, which crosses
the slow Windows/Linux boundary described above. Measured:

                              1st load   2nd / 3rd load
  /up (Laravel boot only)     0.17 s     0.10 s / 0.12 s
  /admin/login (HTML)         0.16 s     0.15 s / 0.16 s
  admin.css from Vite         34 s       0.007 s / 0.007 s

The result is kept in memory, so it only happens again after the node
container restarts (docker compose up, restart, or a vite.config.js change).

Ways to fix it (most effective first)
-------------------------------------
1. Move the project into the WSL Linux filesystem (see "Further speed-up"
   above). Fixes the root cause: the build would take a second or two, and
   the polling file watcher in vite.config.js would no longer be needed.
2. Warm the stylesheets when the node container starts: once Vite is up,
   request resources/css/admin.css and resources/css/app.css in the
   background, so the build happens before anyone opens the site.
3. Limit what Tailwind scans with @source rules in the CSS files (only
   resources/views and resources/js). Shortens the build, but doesn't
   remove the first-load wait.
